# Anti-Slop: Engineering & Interface Standards

Follow these rules whenever designing, writing code, creating interfaces, or authoring documentation.
The goal: everything should feel **crafted by an intentional human engineer**, not generated by generic AI slop.

## 1. Zero AI Slop in Code
- Code comments must explain **WHY** something was done, never restating what the code obviously does.
- Reject generic boilerplate classes, empty interfaces, or decorative wrappers with zero domain logic.
- Avoid hollow placeholders, stub functions that do nothing, or multi-layered factories for single implementations.

## 2. Zero AI Slop in Copy & Documentation
- Write direct, purposeful, crisp prose.
- Ban marketing buzzwords: "revolutionary", "seamless", "cutting-edge", "game-changer", "harnessing the power".
- State technical facts, commands, options, and error cases explicitly.
- Provide concrete input and output examples.

## 3. Zero AI Slop in UI Design
- Interfaces must be purpose-driven, functional, responsive, and accessible.
- Ban gratuitous gradients, arbitrary rounded glassmorphism badges, and visual noise without semantic meaning.
- Layouts must prioritize usability: clear typography, generous spacing, high contrast, responsive states, and intuitive actions (drag-and-drop, clear status indicators).
